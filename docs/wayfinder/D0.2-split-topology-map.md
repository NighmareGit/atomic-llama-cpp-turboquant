Per-token wall time is dominated by serial split dispatch, not raw compute. The total of individual compute times exceeds the per-token wall clock by ~2-3x because backends run sequentially. The bottleneck is the aggregate serial dispatch pipeline, not any single backend.

## 6. Blocking Dependencies

### 6.1 Serial Split Dispatch (Primary Ceiling)

| Property | Value |
|----------|-------|
| **Source** | `ggml_backend_sched_compute_splits()` in `ggml/src/ggml-backend.cpp` |
| **Mechanism** | `for (split_id = 0; split_id < n_splits; split_id++)` -- each iteration must complete before the next starts |
| **Impact** | ~91% serial dispatch; `overlap_pct` measured at 0.1-0.2% across all topologies |
| **Evidence** | `stall_ratio=0.888` (2-GPU), `0.701` (4-GPU B+13). `input_wait_copy_ms` (7909.6) >> `graph_compute_async_ms` (926.6) -- 8.5x wait vs compute. |
| **Fix path** | GPipe client scheduler: decouple dispatch from completion, allow stage i+1 to start when stage i finishes for token T+1 |
| **Path-B+ result** | B+14 wavefront tried; NULL on M3. `global_3bk` < 1%. **Structural ceiling.** |

### 6.2 Autoregressive Sample Gate

| Property | Value |
|----------|-------|
| **Source** | `llama-context.cpp` -- token `T+1` unknown until `T` forward+sampled |
| **Mechanism** | Single-sequence decode: all splits for T must complete before sample yields T+1 |
| **Impact** | RPC0(T+1) cannot start until RPC_n(T) finishes. Blocks GPipe mode without MTP |
| **Evidence** | `rpc_rtt_per_token=0.52ms` but per-token wall=5ms (2-GPU) or 14ms (4-GPU) -- serial dispatch pipeline, not RPC latency |
| **Fix path** | GPipe mode A: MTP/NextN draft provides known-ahead tokens; or multi-sequence microbatches |
| **Constraint** | Cannot overlap RPC0(T+1) || RPC1(T) without breaking the sample gate |

### 6.3 KV Write Ordering

| Property | Value |
|----------|-------|
| **Source** | KV cache write in gather split (ROCm0) |
| **Mechanism** | KV write must complete for T before split 0 of T+1 reads KV for attention |
| **Impact** | Gather split blocks dispatch of T+1. Measured `event_sync_slot_ms=2705` (2-GPU blocking-audit-c) |
| **Evidence** | `WAIT_DOMINATES_COMPUTE` verdict in phase12c audit |
| **Fix path** | Producer-consumer event signaling across splits; GPipe stages release on event, not completion of all writes |

### 6.4 RPC Flush/Drain

| Property | Value |
|----------|-------|
| **Source** | `ggml-rpc.cpp` EVENT_RECORD drain at split boundaries |
| **Mechanism** | Each split flushes RPC command queue via EVENT_RECORD; drain accumulates at token boundary |
| **Impact** | `drain_flush_ms=7129.6` (2-GPU), 4584.5 (4-GPU B+13). EVENT_RECORD=1540 events totaling 7082.8ms |
| **Evidence** | `EVENT_RECORD_DOMINATES_DRAIN` in phase12c audit. B+9/B+12 deferral NULL on overlap |
| **Fix path** | B+13 reduced drain via producer-slot wait. Remaining drain is structural -- GPipe can overlap drain with compute |

### 6.5 Blocking Dependency Summary

| Dependency | Source | Impact | Path-B+ Result | GPipe Fix |
|------------|--------|--------|---------------|-----------|
| Serial split dispatch | ggml-backend.cpp | 91% serial | **Structural ceiling**; B+14 NULL | Decouple dispatch from completion |
| Sample gate | llama-context.cpp | T+1 blocked | **Fundamental** to single-seq | MTP coupling + GPipe stages |
| KV write ordering | KV cache | Gather waits | Produces `WAIT_DOMINATES_COMPUTE` | Event signaling between stages |
| RPC flush/drain | ggml-rpc.cpp | EVENT_RECORD sum | B+13 reduced 36% | Overlap drain with next-token compute |
| RPC tail spikes | Network | p99=71.55ms | B+12 defer helps | Mitigate with timeout + retry |

## 8. Recommendations for GPipe

### 8.1 Critical Path Items

1. **Split 1-2-3 (RPC compute splits) are the compute targets.** Overlap dispatch across these three RPC endpoints. The straggler (romulus 3060 docker, ~7.4 ms/tok on 4-GPU) determines the cycle time.

2. **Split 4 (gather) must wait for all upstream splits.** GPipe stage release must ensure gather inputs are ready before firing gather on token T.

3. **KV write ordering is the tightest constraint.** Gather split writes KV cache for token T. T+1 needs KV read. Producer-consumer event signaling can release T+1 dispatch as soon as KV write completes, not after full gather split.

4. **RPC hop latency is acceptable for overlap** (p50=0.35ms). The serial dispatch loop is the bottleneck, not RTT. Tail spikes (p99=71.55ms) need mitigation via timeout/retry.

5. **Sample gate blocks cross-token overlap** for single-sequence decode without MTP. GPipe mode A (MTP/NextN) provides known-ahead draft tokens that break the dependency.

### 8.2 Suggested GPipe Stage Splitting

The natural split boundary after the sample gate is:

```
Stage 0: embed(T) + layer compute(T) on RPC0-2
Stage 1: gather(T) on ROCm + sample(T) -> T+1
Stage 2: embed(T+1) + layer compute(T+1) on RPC0-2  (overlaps with Stage 1)
```

This creates a 2-stage pipeline where gather + sample overlaps with the next token's RPC compute.

### 8.3 Priorities for D0.3 (KV-ordering grilling)

- Determine exact KV write locations within the gather split
- Identify minimum release point (KV written before logits computed?)
- Evaluate producer-consumer event API in ggml-backend
